# Arquitetura Visual

## Objetivo

A arquitetura visual do GESTISAC transforma a referencia enviada num sistema consistente. O objetivo nao e criar um dashboard bonito isolado, mas uma linguagem visual reutilizavel para toda a plataforma.

O produto deve parecer:

- Um sistema operativo premium.
- Um cockpit fintech.
- Um command center empresarial de nova geracao.
- Uma plataforma viva, elegante e confiavel.

## Principios Visuais

### Hierarquia Antes De Decoracao

Cada efeito visual precisa de uma funcao:

- Profundidade separa camadas.
- Glow indica importancia.
- Cor identifica dominio.
- Movimento confirma estado.
- Espaco reduz ruido cognitivo.

### Visao Geral Antes De Densidade

As paginas devem abrir com contexto, metricas e acoes. Listas e tabelas entram depois, como detalhe operacional.

### Premium Sem Excesso

O visual deve ser rico, mas nunca barulhento. O sistema deve evitar neon agressivo, transparencias que reduzem leitura e elementos decorativos sem funcao.

## Camadas Da Interface

### Layer 0: Atmosfera

Fundo dark navy com iluminacao radial subtil. Esta camada cria a sensacao cinematica e tecnologica.

### Layer 1: Shell

Sidebar, topbar e area principal. A shell deve parecer fixa, estavel e institucional.

### Layer 2: Paineis

Glass panels para dashboard, filtros, grupos de metricas e secções de pagina.

### Layer 3: Cards Operacionais

Grandes cards dos modulos centrais. Sao os elementos de maior presenca visual depois da saudacao.

### Layer 4: Componentes De Acao

Botoes, quick actions, badges, menus, tabs, notificacoes e CTAs.

### Layer 5: Feedback

Toasts, loading states, focus states, empty states, validacoes e alertas.

## Dominio Visual Por Modulo

- Condominios: azul profundo, ciano suave, arquitetura, ordem e estrutura.
- Contabilidade: dourado, verde financeiro, brilho controlado, precisao.
- Administracao: roxo e azul, operacao, ferramentas, progresso.
- Relatorios: dourado e laranja, graficos, inteligencia, conclusao.

## Regras De Consistencia

- Cada modulo tem uma cor principal, mas todos vivem dentro do mesmo navy base.
- Cards importantes podem ter ilustracao ou simbolo forte; cards secundarios usam icone e metricas.
- Acoes destrutivas ou urgentes usam cor contextual, mas sem quebrar a estetica premium.
- A mesma informacao deve ocupar a mesma posicao relativa entre modulos sempre que possivel.

## Anti-padroes

- Layout tipo ERP com sidebar pesada e conteudo em tabelas densas.
- Cards identicos sem identidade emocional.
- Gradientes aleatorios por componente.
- Sombras duras e sem profundidade real.
- Efeitos glass que dificultam leitura.
- Animacoes que chamam mais atencao que o conteudo.
